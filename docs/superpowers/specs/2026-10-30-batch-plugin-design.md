# DSH 插件批量开关设计

用户目标：交付独立、可安装和发布的 DSH 插件；启用后在插件管理及插件市场合适位置出现“一键停用”“一键启用”。启用恢复批停前的列表，保留本来关闭的插件。

实现选择：沿用 rc.3/rc.5 兼容的官方 pluginManager 开关和受连接认证保护的 Fetch 路由，不修改 DSH 或市场源码。前端通过原生 plugins.tab / add.actions 提供稳定入口；兼容层在官方插件页公共 header 内部末尾插入本插件拥有的工具条，与标题同行靠右，窄屏允许换行，保留官方已有节点的位置；独立 dshmarket 面板仍在根顶部插入工具条。相较直接修改市场包，独立扩展更易随市场更新保留；相较只提供管理标签页，工具条可在市场更新时直接使用。

批停只处理已安装、已启用、可管理的第三方 bundle；跳过官方组件、readOnlyReason、缺失/错误包、本插件与触及自身 row 的覆盖、市场载体 dshmarket。核心和恢复入口必须保持可用。每一步先保存待执行记录再调用官方接口；串行执行并保留部分失败结果。异步作业通过status轮询，避免长请求。不得把 changed 当作已应用。

快照在 profileContext.dir 的 .dsh-plugin-batch-toggle 下原子保存并与profile绑定。互斥锁阻止并发和跨进程批操作；未恢复快照不能被新一轮覆盖。重启后根据实际bundle状态恢复；已卸载项跳过，原来关闭的包不会启动；恢复失败保留待恢复项供重试。只恢复被批停或中断时可能批停的项。按原目标顺序启用；公开API无法保证与受保护层交错的全局层次完全复原，明确记录此限制，不直接写profile清单。

所有状态与批操作接口通过 ctx.connection.fetch 注册，使用 DSH 现有 Owner 认证及同源限制。无任意包名请求参数、无额外服务器、无需模型密钥。按钮显示进行中、成功、失败和重启要求，并有结果面板，不能把部分完成显示成全部成功。

发行包含 MIT 许可、npm元数据、DSH bundle补丁、前后端预编译代码、中英文介绍、安装与收录指南。预编译tgz可本地/GitHub Release安装。公开仓库、npm发布和提交收录属于外部发布，先交付可审阅包，发布前再取得必要的账户信息和明确授权。收录由市场维护方决定；不承诺已收录。

验证：状态机与真实文件存储测试、接口鉴权测试、市场/管理页DOM接入测试、隔离DSH安装和批停/重启恢复测试、tgz内容检查、独立代码审查。运行验证rc.3；rc.5相关官方接口源码已比对一致，未据此声称完成rc.5运行测试。
